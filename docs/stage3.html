Stage 3 · Week 4 · difficulty 5–6/10

Explainability — the heatmaps

For every prediction, draw a heatmap of which pixels the model actually used. This stage builds two kinds of heatmap — and, crucially, checks that they genuinely depend on the model before anyone trusts them.

Deliverable: heatmaps + a passed sanity check Methods: Integrated Gradients, Grad-CAM Subset: 2,000 images

1 What is a heatmap?

When the model says "cat", a heatmap (or "attribution map", or "saliency map") colours in the pixels that pushed it toward that answer — bright where they mattered, dark where they didn't.

The project's whole question is whether these heatmaps wobble in a useful way when images are corrupted. But first we need to produce them reliably, in two complementary ways, and prove they aren't just reacting to the picture regardless of the model.

2 Two ways to make a heatmap

Primary

Integrated Gradients

Starts from a black image and fades up to the real one in 32 steps, adding up how sensitive the prediction is to each pixel along the way. Fine-grained, and it works on any differentiable model (so it transfers to the Vision Transformer later).

Secondary

Grad-CAM

Looks at the last convolutional block (layer4) and weights its 4×4 feature map by how much each region pushed the prediction up, then stretches it to 32×32. Cheap and robust, but coarse.

Target class
the class the model predicted (the realistic case — the true label is unknown at deployment)
Map
absolute attribution, summed over colour channels → a non-negative 32×32 map
Image subset
a fixed 2,000 images (200/class), split into halves F (fit) and H (held-out) by image identity

3 The sanity check — do the heatmaps even depend on the model?

A heatmap can look convincing while explaining nothing. Some methods mostly trace the edges in the image and would draw the same pretty picture even for a random, untrained model. The Adebayo et al. (2018) test catches this.

The test: take the trained model, compute its heatmaps, then scramble its weights layer by layer from the top down. Recompute the heatmaps each time and measure how much they still match the originals (Spearman correlation).

  • ✓A trustworthy method → the heatmap should fall apart as the model turns to noise (correlation drops toward 0).
  • ✗A broken method → the heatmap barely moves, proving it was never really about the model.

Integrated Gradients is flagged — and this is not a bug. It only falls to ~0.41, which is exactly the Adebayo finding: gradient methods like IG partly behave like edge detectors and stay correlated with the image even on a random model. It's a caveat to report, not an error to fix — and evidence that, here, Grad-CAM is the more model-faithful map.
