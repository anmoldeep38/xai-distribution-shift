Setup & Pre-registration

Before touching a single experiment, the entire study is written down and locked. This stage turns a vague idea into a falsifiable, public research protocol — so the results that come later can be trusted.

Deliverable: frozen protocol + public repo Frozen: 2026-11-25 Repo: github.com/anmoldeep38/xai-distribution-shift

1 Why pre-register at all?

A pre-registration is a time-stamped, public document that fixes the hypotheses, the exact way they'll be measured, and the design choices — before any result is seen.

The problem

Cherry-picking

With enough metrics and splits, you can almost always find some combination that looks like a positive result. Deciding what counts as success after seeing the data is how false findings get published.

The fix

Decide first, then test

The primary hypothesis, the single metric that judges it, and the pass/fail rule are all committed up front and pushed to a public Git commit. The commit's timestamp is the proof.

In this project: the protocol lives in README.md, and the first public commit (82808ae, 2026-11-25) is the pre-registration. Any later change to the primary hypothesis, primary metric or evaluation rule must be logged with a date and reason — nothing is edited silently.

2 The research question

When an image classifier meets corrupted images (blur, noise, fog…), its heatmaps — the picture of where it "looked" — change. The question is whether that change is useful: does it warn us about mistakes that the model's confidence score doesn't already reveal?

Primary — RQ1

Does perturbation-based local heatmap instability provide incremental information for detecting individual classification errors under image distribution shift, beyond maximum-softmax confidence and predictive entropy, and does it generalise to unseen corruption families?

Secondary — RQ2

Does aggregate attribution-profile drift track condition-level model degradation, and does it provide information complementary to conventional performance indicators?

3 The anchor paper

The study builds on, and stress-tests, one recent paper from the tabular machine-learning world.

Masood et al. (2026) — Explanation audits reveal silent failures of machine learning models under distribution shift. Discover Artificial Intelligence 6, 890. doi:10.1007/s44163-026-02012-6 (verified via Crossref, 2026-11-23)

They separated two kinds of explanation monitoring on tabular data:

  • ALocal volatility — does one row's attribution change under a small perturbation? A per-sample score. Weak error detector: AUROC 0.575 vs 0.866 for confidence.
  • BBatch drift — does the whole batch's average attribution move away from clean? One score per batch. Tracked error well: Spearman 0.681 with realised error.

This project asks whether that local-vs-batch distinction transfers to computer vision — a genuinely different setting (images, CNNs/ViTs, natural corruptions).

4 Hypotheses

Each is written so it can fail. H1 is the only confirmatory test; H2–H6 are secondary.

PRIMARY · H1

Local heatmap drift adds error-detection value on unseen corruptions

Operational local drift adds information for detecting individual errors on unseen corruption families, beyond confidence and entropy.

Test: E4 vs E3, leave-one-corruption-family-out. Supported only if the pooled held-out ΔAUROC has a cluster-bootstrap 95% CI excluding zero and is positive in at least 3 of the 4 held-out families (ResNet-18, IG, predicted class, 3 seeds).

H2

Batch-level attribution drift is positively associated with condition error rate.

H3

Drift still helps after accounting for corruption severity (E6 vs E5).

H4

The value of drift differs between Integrated Gradients and Grad-CAM.

H5

Confidence + drift gives lower selective risk than confidence alone (90/80/70/60% coverage).

H6

Drift adds information beyond output-level consistency — i.e. it is more than output instability (E8 vs E7).

5 The eight monitors (E1–E8)

Each is a small logistic model predicting "is this prediction wrong?". Compared pairs differ by exactly one feature group, so any gain is attributable.

Severity is an oracle variable — unknown at deployment — so E5/E6 are controls, not deployable monitors. If drift only helps by proxying severity, E6 will not beat E5.

6 Frozen design decisions

These values are fixed before the main experiments. Changing any of them after the freeze needs a change-log entry.

How "drift" is measured (operational, deployable)

D(x) = (1/K) · Σk  d( A(x), A(Tk(x)) )
Perturbation Tk
Gaussian pixel noise, σ = 0.01 (4× milder than CIFAR-10-C's mildest noise), clipped to [0,1]
K (copies)
8, with a fixed seed per image
Distance d
1 − Spearman (primary); normalised L1 and cosine (secondary)
Attribution target
the class predicted for x (true class only as a diagnostic)
Primary method
Integrated Gradients (Captum, black baseline, 32 steps)
Secondary method
Grad-CAM (layer4, 4×4, bilinear→32×32)
Why perturbation-based: at deployment the clean version of a corrupted image doesn't exist, so drift is measured against a slightly perturbed copy of the input we do have. Clean-vs-corrupted drift is kept only as a diagnostic.

Batch-level drift (Track B)

Profile
|IG map| pooled to an 8×8 grid, normalised to sum 1
Clean reference
1,000 validation images (100/class, fixed)
Drift
Jensen–Shannon distance vs the reference, 200 bootstrap batches of 500

Data splits & the leakage guard

Train / val
45,000 / 5,000 (seed 0); model chosen on validation only; test touched once
Explanation subset
2,000 test images (200/class), split into halves F (fit) and H (held-out) by image identity
Primary evaluation
leave-one-corruption-family-out: fit on 3 families, test on the 4th; rotate
Families
noise · blur · weather · digital

Statistics

Resampling
cluster bootstrap by image identity, 2,000 resamples
Seeds
3 training seeds; a result holding in <2 of 3 is flagged unstable
Metrics
AUROC, AUPRC (+ prevalence), AURC, risk@coverage, ECE, Brier

7 Prior work & the gap

The two closest papers were read in full before freezing, so the novelty claim is honest.

Already known

Heatmaps degrade

Hovakimyan & Bravo (2026) show Grad-CAM maps degrade under corruption — but never use that drift to detect errors. "Degradation" can't be our claim.

Neighbouring

Output consistency

Kalita & Singh (2026) test output-level consistency beyond confidence on CIFAR-10-C: +0.13 AUROC on noise when seen in training, but only +0.002 on unseen noise. No saliency at all.

Open gap

Our question

Does heatmap (not output) instability add error-detection value beyond confidence, entropy and severity — on unseen corruption families? Not answered yet.

Either outcome is publishable: a negative H1 extends Kalita & Singh's "doesn't generalise" result from outputs to explanations; a positive H1 shows explanations carry failure signal that outputs don't.
